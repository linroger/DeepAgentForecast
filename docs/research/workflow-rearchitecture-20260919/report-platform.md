## 1. Main conclusion and recommended first slice

The smallest useful architecture change is a **shared, explicit report-context factory**, followed by caller-parity tests. There is already considerable report generation, publication, translation, visualization, and export protection. Replacing those subsystems would discard tested behavior without addressing the immediate defect: different report entry points receive different research artifacts, and several downstream readers rediscover ownership by scanning pipelines for a simulation ID.

The primary pipeline passes `quantitative`, `contested`, `timeline_events`, `graph_priors`, and `graph_priors_structural` at `backend/app/services/pipeline_orchestrator.py:12911`. The direct generate API passes only brief/actors/sources/research Markdown at `backend/app/api/report.py:191`; chat repeats that constructor at `:1317`; seed reports use the smaller dictionary at `backend/app/services/pipeline_orchestrator.py:8488`; model comparison does the same at `backend/scripts/model_comparison.py:223`. These are current source differences, not a performance inference from historical runs.

Chat needs a consumer fix as well as a constructor fix. `backend/app/services/report_agent.py:10988` formats only the requirement, a prefix of the published report, and tool descriptions. It never calls `_prepend_research_background` (`:2274`) and never uses the constructed quantitative/contested/timeline/source blocks. Merely adding constructor arguments would leave that gap open.

Output health is distinct from input provenance. `ReportManager.publication_status` (`backend/app/services/report_agent.py:11527`) verifies final Markdown/forecast fingerprints and policy, but does not prove which owner handoff and source revisions entered generation. Visualization input hashing is useful (`backend/app/services/report_visualizer.py:4661`), but a directory string hash is not a hash of files subsequently read from that directory.

The parent owns coordinator changes and REPORT stage registration. The parent-confirmed registration boundary at `pipeline_orchestrator.py:9176` is treated as an interface observation, not a separate coordinator audit here.

## 4. First proposal: narrow report-context factory and caller parity

**Proposed module:** `backend/app/services/report_context.py`; proposed tests `backend/tests/test_report_context.py` and `test_report_entry_context_parity.py`. These paths do not exist as part of this study and have not been created. Implementation requires the parent's approved `PLANS.md`.

### 4.1 Boundary

Introduce a small immutable value object plus a loader/factory that resolves already-existing artifacts once. It should produce existing `ReportAgent` kwargs, a diagnostic missing-input list, and a provenance receipt. It must not generate prose, initialize an LLM/graph client, query markets, launch services, alter pipeline state, repair source artifacts, or change actor permissions.

Inputs: explicit pipeline/run owner if available; actual simulation ID; graph/project IDs; report requirement; scenario label/base simulation ID; optional seed/scenario spine; resolved handoff location and existing owner manifest supplied by the coordinator adapter. Keep simulation identity and shared research ownership separate. An API adapter may use the existing simulation lookup only for genuine legacy records, recording ambiguity/unverified lineage rather than selecting arbitrary first-match evidence as verified.

Loaded values: `actors`, `sources`, research Markdown, derived `situation_brief`, `quantitative`, `contested`, `timeline_events`, `graph_priors`, `graph_priors_structural`. Include a pinned market snapshot/history reference in the receipt; do not invent a constructor argument or turn loading into a market refresh in the first patch. Preserve the primary path's intentional omission of research charts from report prose. Keep original `[S<n>]` positions; never compact the source list by dropping rejected rows.

The receipt should bind schema/version, actual report/simulation/graph/project IDs when assigned, research owner identity, artifact logical names, paths relative to the declared owner root, hashes of the exact bytes read, schema checks, presence state, and relevant context policy. Validating and decoding the same read bytes avoids a hash/read race. Hash equality proves byte identity; it is not proof that evidence is true, current, or authorized. If a registered artifact fails identity/hash/schema checks, fail with a typed integrity error; distinguish that from a truly absent optional legacy artifact. Never silently erase a known integrity failure into `None`.

Preserve actor evidence audience/permission markings and source bindings without widening them. A report-modeler evidence view is not an actor prompt. The factory must not feed modeler-only or denied claims into shared actor knowledge, recompute sealed actor context, infer new permissions, or reclassify simulations/graph structure as sourced facts. Reuse parent/actor-owner validation where available; do not create a second actor-authority implementation.

### 4.2 Adoption order and minimal footprint

1. Characterize current rich constructor behavior using a complete synthetic handoff. Add factory with the same kwargs and legacy empty-input behavior.
2. Replace direct API and model-comparison dossier assembly with the factory. Parent wires the main and seed call sites with explicit owner context; this reviewer does not propose rewriting coordinator control flow.
3. Update chat to actually consume a bounded, provenance-labelled evidence view and the audited report's citation map. Prioritize relevant report sections and stable source IDs instead of relying solely on a fixed head slice. Preserve the response envelope; add real citation/source records additively while retaining the legacy queries field if clients depend on it. Only user/assistant text belongs in caller-supplied chat history; reject/control role spoofing before LLM invocation.
4. Let visualization consume the pinned context values, avoiding fresh owner scans. Materialize market-history bytes before computing input fingerprints. This can be a second small commit after constructor parity, not a prerequisite rewrite of the renderer.
5. Persist the context receipt as an additive report artifact. Parent decides its REPORT registration and reuse relationship. Old published reports without a receipt remain explicitly legacy; do not relabel them provenance-verified or require a paid regeneration simply to view them.

## 6. Existing protections to preserve

- **Publication authority:** completed + nonpartial + hard-pass audit + current policy + matching Markdown and forecast hashes (`report_agent.py:11527`). Final audit is read-only with respect to published Markdown (`:7660`); deterministic stabilization precedes it. Old policy needs deterministic replay, not silent acceptance.
- **Citation identity:** original positional IDs retained (`report_agent.py:2229`); semantic grounding and market/proposition/scenario checks exist. A context factory must not renumber sources or turn output hashes into source-truth guarantees.
- **Translation:** independent artifacts and exact source/report/language identities, section token protection, bounded repair, and retry leases (`report_agent.py:6627`, `:11275`, `:11463`, `:11558`). Worker context propagation already exists (`:6684`); do not re-report that historical gap as current.
- **Parallel sections:** body workers inherit ContextVars (`report_agent.py:9321`); summaries run after body. Default concurrency is already six (`config.py:1480`). Raising concurrency is not the first recommendation; recovery and request-local accounting are more concrete gaps.
- **Forecast epistemics:** actual prompt-signal allowlist (`forecast_extractor.py:1146`), retained claimed source on downgrade (`:1179`), scenario/binary reconciliation (`:2404`), interval source and sample-count labels (`:3084`). Spread is not an empirically calibrated confidence interval.
- **Visualization restraint:** density/comparability checks; driver-keyword tornado and evidence-tier-weight chart are excluded from ordinary reader output (`report_visualizer.py:4427–4441`); missing data is recorded, not fabricated. Safe chart containment and sandboxed/no-network HTML/SVG serving (`api/report.py:1060–1112`) should remain.
- **Storage:** sibling-temp atomic writes (`utils/atomic.py:20`) prevent partial-file readers; they do not by themselves serialize read-modify-write transactions or guarantee a multi-file bundle snapshot. Translation/PDF locks add narrower coordination. Project writes use atomic replacement (`models/project.py:168`) but remain whole-object saves.
- **LLM resilience:** bounded retry/fallback, deterministic authentication/model-failure cooldown, breaker fast-fail, and fallback usage not double-recorded (`llm_client.py:414–477`, `:514–567`). Cache is optional/bounded (`telemetry.py:530`); budget semantics remain separate from caching.
- **Evaluation separation:** production calibration excludes golden/characterization rows even in mixed historical files (`forecast_ledger.py:48`, `:243`); live rubric judging is opt-in (`eval_forecast_quality.py:333`). Market JSONL has a dedicated idempotency lock (`forecast_ledger.py:349`).
- **Application lifecycle:** Flask test-process guard prevents orphan cleanup/signals when constructing test apps (`app/__init__.py:71`); non-loopback API access requires a token (`:99`), logs redact structured secrets, production responses remove traceback (`:132`). `TaskManager` remains process-local, not a durable coordinator.

**Prompt consistency follow-up:** The outline prompt still describes internal simulation outputs as evidence and instructs turning behavior statistics into real-world conclusions (`backend/app/services/report_agent.py:675–692`), while the section prompt explicitly permits only research as factual evidence and forbids fabricated institutional viewpoints (`:765–790`).
