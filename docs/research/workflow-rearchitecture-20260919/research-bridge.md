## Findings that matter for the architecture decision

The bridge already has useful boundaries worth preserving: isolated evidence lanes, a checksum-bound global synthesis manifest, producer-owned actor/source/claim identities, scoped evidence receipts, exact report-judge binding, shared model/tool admission, and parent-side generation promotion. The 17,219-line research driver puts those boundaries in one module, but replacing the whole driver is not the first repair. The most urgent issue is the newly added linear engine crossing those same boundaries with materially different semantics.

In this baseline, the linear engine is **not a contract-equivalent replacement** for hybrid research. Its dispatch accepts evidence-only/global-synthesis requests but runs its own full research pipeline; its retrieval adapter calls an async-only tool synchronously; its planner/gap templates contain unescaped JSON braces passed to str.format; its state lacks run/question identity; and its completion markers can precede durable notes. Its separate source ledger does not reach the existing receipt-bound extraction interface. These are source-proven defects or mismatches, with affected scenarios and bounded proposals in §6.

The parent provides meaningful protection: full runs whose pinned policy requires actor intelligence reject a missing or invalid actor plane before ONTOLOGY/GRAPH. That does not make the linear path correct: it can spend the research budget before rejection, and research-only/legacy-policy routes have different acceptance behavior. Preserve the parent gates; repair the producer and admission negotiation.

A second high-value boundary is context compaction. This checkout has whole-segment summarization settings, but summary failures become ordinary strings and message replacement proceeds. The research evidence collector excludes the resulting untyped human summary. The later ASTRA compaction-receipt repair described in memory is **not present in these reviewed bridge sources**; it must not be credited to ec29ab1. Reusing a reviewed repair from another worktree would require a separate compatibility review and approved plan.

No production speedup, current provider availability, real spend total, test pass rate, or complete end-to-end correctness is claimed. Historical cost figures in code comments were not re-audited against saved runs.

### Hybrid research: the three separate kinds of parallel work

1. **Outer evidence lanes belong to the parent.** When there is more than one track and global synthesis is enabled, each lane is launched with evidence-only mode. The broad baseline alone owns the shared actor dossier; other angles own Track-A evidence. The parent limits concurrent lanes, subagents and model streams, then constructs a v3 evidence manifest and runs one global synthesis, with two bounded synthesis attempts in private directories. Failed synthesis does not inherently require another evidence run. See [pipeline_orchestrator.py:10700](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:10700), [pipeline_orchestrator.py:10833](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:10833), [pipeline_orchestrator.py:11049](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:11049), [pipeline_orchestrator.py:11091](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:11091).

2. **Track A and Track B belong to one child.** Track A produces broad research notes/report; Track B produces the actor dossier and coverage/judge plane, on distinct thread IDs with the same client. The child can run them concurrently or sequentially. A Track-B exception may initially degrade to no dossier, but later actor-required gates can still reject the run. Evidence-only baseline lanes also require the actor plane when explicitly assigned that ownership. See [deerflow_research.py:16346](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:16346), [deerflow_research.py:16438](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:16438), [deerflow_research.py:16525](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:16525), [deerflow_research.py:17169](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:17169).

3. **Scoped workers belong to the agent/bridge research loop.** Native task delegation and legacy bridge KIQ fan-out are intentionally alternative breadth mechanisms. Independent deep phases can also use isolated threads and compact prior notes. A local executor limit bounds scheduling; shared SQLite leases bound actual provider calls across processes. Treating all these limits as the same “number of agents” would hide multiplicative load. See [deerflow_research.py:4473](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:4473), [deerflow_research.py:10027](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:10027), [deerflow_research.py:12095](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:12095), [deerflow_research.py:4434](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/deerflow_research.py:4434).
